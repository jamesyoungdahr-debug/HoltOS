IN PROGRESS: "FORK KDE" — HOLTOS-OWNED GLASS
--------------------------------------------
Liam does not like the current glass look (Klassy 70 % title bars, Kvantum
70 % windows, KWin blur 11) and wants full control, so the desktop chrome
is being forked into HoltOS-owned code built by our pipeline:

1. holtos-glass-effect  (C:\projects\holtos-glass-effect, git, local only,
   NOT yet on GitHub). A KWin effect forked from KWin 6.7.5's built-in
   blur (src/plugins/blur) and built OUT OF TREE against the installed
   KWin headers (Arch's kwin package ships them). Plugin id "holtosglass";
   config group [Effect-holtosglass]; replaces stock blur
   (kwinrc: blurEnabled=false, holtosglassEnabled=true).
   Status: DONE (milestone 1, 2026-09-12 06:28): the unmodified fork
   builds and packages — local-repo/holtos-glass-effect-0.1.0.r5-*.pkg
   (build attempt 5; fixes on the way: stale pacman db, Vulkan/wayland/
   libdrm makedepends, link libxcb, K_PLUGIN_CLASS inside namespace).
   Milestone 2 DONE (06:32): feature port committed (bf8b6dd, 2ed60b8)
   and building: holtos-glass-effect-0.1.0.r7.2ed60b8 in local-repo/.
   Implemented: force blur (windows/decorations/menus, docks optional,
   ExcludeClasses), Contrast/Brightness, TintColor+TintStrength,
   CornerRadius for undecorated windows, settings module for all.
   SEEN ON SCREEN (06:39): package installed into the build-8 VM over
   SSH (holtos@172.20.176.251, key scratchpad/vmkey), stock blur
   unloaded, holtosglass loaded (qdbus6 org.kde.KWin /Effects
   loadedEffects). Red-tint test proved blur+tint reach every
   translucent window region (Falkon toolbar pixel went wine-red).
   SETTLED (06:50): the title bar is translucent (30 % test went darker)
   but KWin 6.7 reports the Klassy decoration as having no alpha, so
   neither stock blur nor the fork blurred under the frame. Fix 2a54c2f:
   force-blur the frame whenever a decoration exists. Needs rebuild
   (effect build 7) — do it after the decoration build finishes, the
   two share local-repo/ and repo-add.
   Live-tuning recipe in the VM: kwriteconfig6 --file kwinrc --group
   Effect-holtosglass --key <Key> <value>; qdbus6 org.kde.KWin /Effects
   reconfigureEffect holtosglass. Kvantum opacity: copy the theme to
   ~/.config/Kvantum/HoltOSGlass/ and set reduce_window_opacity=N.
   Planned features (port from Better Blur / kwin-effects-forceblur,
   whose upstream stopped at Plasma 6.4 so it cannot be used directly):
     - force blur behind EVERY window (not only apps that ask), incl.
       decorations, menus; exclude list by window class
     - brightness / contrast / saturation of the blurred background
     - TINT: blend a colour (ink #171423) into the blur so text on
       translucent windows stays readable on any wallpaper
     - corner radius for windows without a decoration radius
     - later: static/fake blur (blur wallpaper once, low GPU cost)
   Reference sources: C:\projects\forks\kwin\kwin-6.7.5 (extracted parts),
   C:\projects\forks\forceblur-ref (Better Blur v1.5.0 + main).
   Key API facts learned: shader colorMatrix is applied as
   color * matrix (translation in the LAST ROW of QMatrix4x4);
   "#include \"sdf.glsl\"" in shaders resolves to :/opengl/sdf.glsl inside
   the kwin process (fine out of tree); BorderRadius(qreal) ctor exists
   (scene/borderradius.h); KWin 6.7 already rounds blur to the
   decoration's border radius.
